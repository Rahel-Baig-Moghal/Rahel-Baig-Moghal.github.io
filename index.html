Cloud Architecture AWS Serverless · Amazon Connect

Relay: Multi-Account CI/CD for Amazon Connect

Safe cross-environment flow promotion (Dev → Staging → Prod) with zero long-lived keys
Why it exists

Moving telephony flows between isolated AWS environments is the hardest operational problem in enterprise contact centers. Teams resort to manual JSON copy-pasting or sharing persistent admin IAM keys across accounts. One broken queue ID drops live emergency calls or sales lines.

How it’s engineered

Relay eliminates long-lived IAM keys entirely. It operates strictly through ephemeral AWS STS AssumeRole sessions partitioned into read-only discovery roles and guarded deployment mutation roles. Every promotion takes an S3-versioned artifact snapshot and logs to a DynamoDB single-table control plane. Before mutating production, Step Function state machines run automated graph diffs and dry-runs, guaranteeing deterministic rollback if validation fails.

03 // PHILOSOPHY

How I think about building software

1. Radical Local-First & Data Sovereignty

If an application cannot work without a remote server ping, it is a leased service, not an owned tool. Whenever I build for people, data belongs on the user's silicon. Local SQLite, native file exports, and zero tracking are not compromises—they are superior engineering.

2. Industrial Pragmatism Over Framework Churn

Simple systems fail simply. Over-abstracted systems fail unpredictably. Whether writing minimal vanilla web frontends, exploring systems programming in Rust, or architecting serverless microservices on AWS, durability and clear failure boundaries trump trendy abstractions every time.

3. Leverage Without Abdication

I use AI as high-leverage machinery. Running open weights locally on Arch Linux gives me private, instant feedback loops. Frontier models handle high-order schema synthesis. But the code, the contracts, and the architectural invariants remain strictly disciplined and verified.

فهم

Fahm: Quranic Vocabulary

Android (com.rahel.fahm) · iOS

Fahm is a 100% offline mobile learning companion engineered to teach high-frequency Quranic vocabulary through 170 progressive mastery levels. It was designed from day one to respect the learner's attention and data.

System Architecture Invariants

Air-Gapped Manifest Enforcement

The application deliberately omits android.permission.INTERNET from its production manifest. The operating system kernel enforces that no outbound network connections can be initiated.

Embedded SQLite Persistence

All spaced-repetition schedules, mastery scores, and streak data live strictly on-device inside user_progress.db. No remote database or synchronization server is ever touched.

Native JSON Portability

Users maintain complete ownership of their study data. At any time, you can export a complete JSON backup to your phone's storage or import a previous backup on a new device.

Distraction-Free Experience

Zero advertising frameworks, zero third-party analytics SDKs, zero user account registrations, and zero tracking telemetry.

Privacy Policy — Fahm: Quranic Vocabulary

Effective Date: October 17, 2026 · Package ID: com.rahel.fahm
Compliance Declaration: Fahm: Quranic Vocabulary operates entirely offline on your local device. The application does not collect, store, transmit, or share any personal user data, device identifiers, or usage telemetry.

1. 100% Offline Architecture & Zero Data Collection

Fahm: Quranic Vocabulary ("the App", package identifier com.rahel.fahm) is developed and published by Rahel Baig Moghal.

  • No Network Permissions: The App requests zero network access. Specifically, android.permission.INTERNET is explicitly blocked in the production Android manifest.
  • No Personal Information Collected: We do not collect, request, store, transmit, or share any personally identifiable information (PII), account credentials, location coordinates, or device identifiers.
  • No Third-Party SDKs or Advertising: The App integrates zero third-party analytics trackers, crash reporting agents, or advertising networks.

2. Local On-Device Storage & User Sovereignty

All study records, level completions, daily streaks, spaced-repetition schedules, and user preferences are stored strictly on your device inside a local SQLite database file (user_progress.db).

  • Backup & Restore: Users may voluntarily export or import their progress as a local JSON file using the operating system's native document picker.
  • Data Deletion: Users can permanently purge all progress via the in-app Profile reset control, by clearing application storage in Android system settings, or by uninstalling the App.

3. Local Notifications

If enabled by the user, daily study reminders are scheduled strictly on-device via the local operating system alarm manager. No external push notification servers (such as FCM) or remote network tokens are utilized.

4. Children's Privacy (COPPA & Google Play Families Policy)

The App is an educational tool suitable for learners of all ages. Because the App collects zero personal data, displays zero advertisements, and performs zero network communication, it complies fully with the Children's Online Privacy Protection Act (COPPA) and the Google Play Families Policy.
